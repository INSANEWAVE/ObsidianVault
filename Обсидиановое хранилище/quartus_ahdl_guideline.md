# Гайдлайн: проект Quartus Prime 25.1std для курсового «ФНЧ Баттерворта (DF2T) на AHDL»

Финальная редакция по итогам проверки вывода Perplexity. Среда: **Quartus Prime 25.1std.0 Build 1129, Standard Edition** (по вашему скриншоту About).

> **Что проверено, а что нет.**
> Числа (коэффициенты, ожидаемые выходы фильтра, погрешности) пересчитаны Python-моделью (scipy `butter` + побитовая целочисленная модель). Пункты меню сверены с методичкой и документацией Altera.
> **AHDL-код в самом Quartus не компилировался** — у меня его нет. Шаблоны написаны по документации AHDL; при первой компиляции возможны мелкие правки. MATLAB-скрипты тоже не запускались в MATLAB: логика идентична Python-модели, из которой взяты «ожидаемые значения».
> Места, которые я не смог проверить именно на 25.1, помечены **(?)** — ориентируйтесь на название пункта меню, а не на его точное расположение.

## 1. Итоги проверки вывода Perplexity

### 1.1 Что в выводе верно (сохранено)

- Порядок работы из методички: отдельная папка на каждый проект, *Empty project*, *Node Finder → List*, *Overwrite Clock*, после смены *End Time* clk задаётся заново, функциональная и временная симуляции, окно результата *Read-Only*, *Create Symbol Files*. Сверено с текстом и скриншотами методички.
- Уравнения DF2T второго порядка и `butter(2, 0.1)` — совпадают с `filter()` / `lfilter()`.
- Принципы: коэффициенты — целые со масштабом 2^Q, округление один раз после накопления, широкий аккумулятор, дополнительный код для отрицательных.
- Сообщение *Design is not fully constrained* для учебного проекта можно игнорировать (так сказано в методичке).

Редакция уже определена: **Standard** (Help → About Quartus Prime — ваш скриншот).

1. Откройте **Tools → License Setup…** и посмотрите, указан ли файл лицензии.

### 0.2 Симулятор — самое узкое место в 25.1

Как это устроено: University Program VWF сам ничего не симулирует. Он строит netlist и запускает внешний `vsim` по пути, заданному в **Tools → Options → EDA Tool Options → строка «ModelSim-Altera»** (в методичке там `…\modelsim_ase\win32aloem`). Начиная с Quartus 21 вместо ModelSim поставляется Questa.

Проверка: в *EDA Tool Options* в строке *ModelSim-Altera* должна стоять папка, где реально лежит `vsim.exe`. Пусто или папки нет — симулятора нет.

**Вариант A (рекомендуется): Questa Starter.**

1. Установщик Questa — на странице загрузки Quartus 25.1, вкладка *Individual Files*. При установке выберите Starter Edition.
2. Бесплатная лицензия — в Self-Service Licensing Center (нужна учётная запись Altera): тип *Fixed*, идентификатор компьютера — *NIC ID* (MAC-адрес сетевой карты без дефисов, смотреть `ipconfig /all`).
3. Придёт файл `LR-…_License.dat`. Положите его в постоянное место и создайте системную переменную `LM_LICENSE_FILE` со ссылкой на этот файл. Перезагрузите компьютер. Проверка: `lmutil lmdiag` в командной строке.
4. **Tools → Options → EDA Tool Options → «…»** у *ModelSim-Altera* → папка `…\questa_fse\win64` **(?)** (точное имя папки в 25.1 найдите по `vsim.exe`).

**Вариант C:** узнать у преподавателя/в лаборатории, какой симулятор и лицензия предусмотрены.

## Этап 2. AHDL-счётчик и первая компиляция

1. **File → New… → Design Files → AHDL File**.
2. Вставьте код:

```ahdl
-- counter_test.tdf
-- 4-bit up counter with asynchronous active-low reset
SUBDESIGN counter_test
(
    clk      : INPUT;
    reset_n  : INPUT;
    q[3..0]  : OUTPUT;
)
VARIABLE
    cnt[3..0] : DFF;
BEGIN
    cnt[].clk  = clk;
    cnt[].clrn = reset_n;          -- clear when reset_n = 0
    cnt[].d    = cnt[].q + 1;
    q[]        = cnt[].q;
END;
```

3. **File → Save As…** → `counter_test.tdf` в папке проекта. Галочка *Add file to current project* включена (как в методичке).
4. Убедитесь, что файл виден в Project Navigator → Files. Если он не назначен верхним уровнем: ПКМ по файлу → **Set as Top-Level Entity**.
5. **Processing → Start Compilation**.

Ожидаемо: Analysis & Synthesis, Fitter, (Assembler), Timing Analyzer — завершены; предупреждения об отсутствии временных ограничений допустимы.

Если ошибки:

| Сообщение                               | Причина                                                             |
| --------------------------------------- | ------------------------------------------------------------------- |
| Can't find top-level / entity undefined | имя файла, `SUBDESIGN` и *Top-level entity* не совпадают (регистр!) |
| Syntax error                            | проверьте `;` после каждого порта и `END;` в конце                  |
| Ошибка лицензии на Assembler            | см. п. 0.1 (для симуляции не критично)                              |

О комментариях на кириллице: Quartus обычно принимает их, но при другой кодировке файла они превращаются в «кракозябры». Проверьте один русский комментарий на этом счётчике; если ломается — в `.tdf` пишите латиницей, а русские пояснения — в записке.

Критерий прохождения: Analysis & Synthesis и Fitter — без ошибок.

## Этап 3. VWF-симуляция счётчика

1. **File → New… → University Program VWF**.
2. **Edit → Set End Time…** → `2 us`. (Сначала время, потом сигналы: после смены времени clk приходится задавать заново — методичка.)
3. Двойной клик по полю *Name | Value at* → *Insert Node or Bus* → **Node Finder…** → **List** → **>>** → OK → OK. В списке должны быть `clk`, `reset_n`, `q[3..0]`.
4. Выделите `clk` → **Overwrite Clock**: Period `100 ns`, Offset `0`, Duty cycle `50 %`.
5. `reset_n`: до 120 нс — 0 (*Forcing Low*), дальше — 1 (*Forcing High*). Сброс отпускайте **на спаде clk, не на фронте** (методичка предупреждает, что вход, изменившийся на фронте, может сработать уже на следующем).
6. Шина `q`: ПКМ → **Radix → Unsigned Decimal** **(?)**.
7. **File → Save As…** `counter_test.vwf`.
8. **Simulation → Simulation Settings** — в командной строке `vsim` замените `-novopt` на `-voptargs="+acc"`. Если такая замена вызывает ошибку — удалите `-novopt` целиком и сохраните. В 25.1 без этой правки функциональная симуляция падает; настройка не запоминается, её нужно повторять в каждом новом `.vwf` (или сохранить исправленный `.vwf`).
9. **Run Functional Simulation**. Результат откроется в отдельном окне *Read-Only*.

**Ожидаемо:** `q = 0`, пока `reset_n = 0`; затем `q` растёт на 1 по каждому нарастающему фронту `clk`: 1, 2, 3, … 15, 0, 1, … (за 2 мкс — 20 фронтов, счётчик один раз переполнится).

Опционально: **Run Timing Simulation** (нужен успешный Fitter) — выход `q` задержан относительно фронта clk, как в методичке.

## Этап 5. MATLAB: коэффициенты и побитовая модель

Код намеренно простой (циклы, без «хитростей»). Три файла в `D:\fpga_kp\matlab\`.

**`calc_coeffs.m`**

```matlab
% calc_coeffs.m - Butterworth LPF coefficients and integer conversion
clear; clc;

Fs = 10000;      % sampling frequency, Hz
Fc = 500;        % cutoff (-3 dB), Hz
N  = 2;          % order (one biquad section)
Q  = 15;         % fractional bits of coefficients

[b, a] = butter(N, Fc/(Fs/2), 'low');   % b0 b1 b2 / 1 a1 a2

B = round(b * 2^Q);          % [B0 B1 B2]
A = round(a(2:3) * 2^Q);     % [A1 A2]   (a(1) = 1 is not stored)

fprintf('b = %.10f %.10f %.10f\n', b);
fprintf('a = %.10f %.10f %.10f\n', a);
fprintf('B = %d %d %d\n', B);
fprintf('A = %d %d\n', A);

% frequency response check: Fc1 = 270 Hz and Fc = 500 Hz
h = freqz(b, a, [270 500], Fs);
fprintf('|H(270)| = %.2f dB, |H(500)| = %.2f dB\n', 20*log10(abs(h)));
```

Ожидаемо: `B = 658 1316 658`, `A = -51151 21016`, `|H(270)| = -0.35 dB`, `|H(500)| = -3.01 dB`.

**`df2t_fixed.m`** — модель, побитово совпадающая с аппаратной реализацией из §10:

```matlab
function [y, nsat] = df2t_fixed(x, B, A, Q, Wd)
% Bit-exact model of the hardware DF2T filter (integer arithmetic)
%   x    - integer input samples (row vector)
%   B    - [B0 B1 B2], A - [A1 A2]  (integers, scale 2^Q)
%   Q    - fractional bits, Wd - data width (bits)
ymax =  2^(Wd-1) - 1;
ymin = -2^(Wd-1);
s1 = 0;  s2 = 0;  nsat = 0;
y  = zeros(size(x));
for n = 1:length(x)
    acc = B(1)*x(n) + s1;                 % scale 2^Q
    yn  = floor((acc + 2^(Q-1)) / 2^Q);   % round to nearest (half up)
    if yn > ymax
        yn = ymax;  nsat = nsat + 1;      % saturation
    end
    if yn < ymin
        yn = ymin;  nsat = nsat + 1;
    end
    s1n = B(2)*x(n) - A(1)*yn + s2;       % s1 uses the OLD s2
    s2n = B(3)*x(n) - A(2)*yn;
    s1  = s1n;
    s2  = s2n;
    y(n) = yn;
end
end
```

**`run_tests.m`** — тесты и погрешности:

```matlab
% run_tests.m - float model vs bit-exact integer model
clear; clc;
Fs = 10000;  Fc = 500;  Q = 15;  Wd = 16;
[b, a] = butter(2, Fc/(Fs/2), 'low');
B = round(b * 2^Q);
A = round(a(2:3) * 2^Q);

A0 = 10000;                 % test amplitude (allowed input is +-0.9*FS = +-29491)
Nn = 200;  n = 0:Nn-1;

names = {'zero','impulse','step','step_updown','sine_100Hz','sine_2kHz','square_250Hz'};
X = cell(1, numel(names));
X{1} = zeros(1, Nn);
X{2} = [A0, zeros(1, Nn-1)];
X{3} = A0 * ones(1, Nn);
X{4} = [A0*ones(1, Nn/2), -A0*ones(1, Nn/2)];
X{5} = round(A0 * sin(2*pi*100*n/Fs));
X{6} = round(A0 * sin(2*pi*2000*n/Fs));
X{7} = A0 * (1 - 2*mod(floor(n/20), 2));      % 250 Hz square wave

FS = 2^(Wd-1);
fprintf('%-14s %10s %10s %10s\n', 'test', 'max|e|', 'e_FS,%', 'e_pk,%');
for k = 1:numel(X)
    x  = X{k};
    yf = filter(b, a, x);                       % ideal (double) model
    [yq, nsat] = df2t_fixed(x, B, A, Q, Wd);    % integer model
    e    = yq - yf;
    emax = max(abs(e));
    eFS  = emax / FS * 100;
    if max(abs(yf)) > 0
        epk = emax / max(abs(yf)) * 100;
    else
        epk = NaN;
    end
    fprintf('%-14s %10.3f %10.4f %10.4f  sat=%d\n', names{k}, emax, eFS, epk, nsat);

    T = table(n', x', yf', yq', e', 'VariableNames', ...
              {'n','x','y_float','y_fixed','err'});
    writetable(T, ['result_' names{k} '.csv']);
end
```

**Погрешность.** Основная метрика — приведённая к диапазону: `e_FS = max|y_fix − y_float| / 2^(Wd−1) · 100 %`. Дополнительно `e_pk` — относительно `max|y_float|` (имеет смысл там, где выход не близок к нулю). Относительная погрешность «в каждой точке» не используется: рядом с нулём она бессмысленна.

Ожидаемые значения (Python-модель, те же алгоритм и данные; в последнем знаке возможны расхождения):

| Тест | max\|e\|, LSB | e_FS, % | e_pk, % |
|---|---:|---:|---:|
| zero | 0 | 0 | — |
| impulse | 4,13 | 0,013 | 0,29 |
| step | 3,47 | 0,011 | 0,033 |
| step_updown | 6,27 | 0,019 | 0,058 |
| sine_100Hz | 6,18 | 0,019 | 0,062 |
| sine_2kHz | 3,71 | 0,011 | 0,26 |
| square_250Hz | 3,80 | 0,012 | 0,035 |

Все значения на порядки ниже допуска 2 %. Тест насыщения (`x = 32767`) выходит за допустимый вход и в оценку 2 % не входит: там `e_FS ≈ 4,5 %` — это отклик на перегрузку, а не ошибка фильтра.

## §10. Архитектура модуля (готовим к написанию AHDL)

### 10.1 Правила арифметики AHDL, из-за которых архитектура выглядит именно так

- В булевых выражениях над сигналами доступны только `+` и `−` (и унарный минус). Операнды-группы должны быть **одной ширины**; число подгоняется под группу, потеря значащих бит — ошибка компиляции.
- Знакового типа нет: расширение знака делается вручную, добавлением копий старшего бита слева, например `(p[33], p[33], p[])` для 34 → 36 бит.
- Арифметического сдвига нет: «сдвиг на 15 вправо» — это выбор диапазона бит, например `y[15..0] = acc_r[30..15]`.
- Округление: `acc_r = acc + 16384` (2^14), затем выбор бит `[30..15]`.
- Насыщение: если старшие биты суммы `acc_r[35..30]` не все равны — значение не помещается в 16 бит; тогда выход = 32767 (при знаке 0) или −32768 (при знаке 1) и устанавливается флаг `sat`.
- Умножение — только `lpm_mult` (этап 4).
- Fs = 10 кГц во временной шкале симуляции **не задаётся**: она зашита в коэффициенты. Один отсчёт = один импульс `start`.

### 10.2 Интерфейс (общий для обеих структур)

| Порт | Направление | Назначение |
|---|---|---|
| `clk` | вход | тактовый сигнал |
| `reset_n` | вход | асинхронный сброс, активный 0 |
| `start` | вход | 1 такт: принять `x` |
| `x[15..0]` | вход | отсчёт (знаковый, доп. код) |
| `y[15..0]` | выход | результат (регистр) |
| `done` | выход | 1 такт: `y` обновлён |
| `sat` | выход | 1, если сработало насыщение |

### 10.3 Структура A — параллельная (эталонная)

Пять умножителей `lpm_mult` работают одновременно, автомата нет, отсчёт обрабатывается за один такт по `start`. Реализуйте её **первой**: она проще для отладки и служит эталоном для структуры B. Цепочка комбинационная: `B0·x + s1 → округление/насыщение → y → A1·y, A2·y → новые s1, s2`.

### 10.4 Структура B — последовательная, 1 умножитель (по варианту)

Один `lpm_mult`; на его входы по состоянию автомата подаются разные пары операндов. Умножитель используется 5 раз за отсчёт:

| Состояние | dataa × datab | По фронту в конце состояния |
|---|---|---|
| — (`start`) | — | `xr ← x` (защёлка входа) |
| S1 | `xr × B0` | `acc ← P + s1` |
| S2 | `xr × B1` | `y ← sat(round(acc))`; `t ← P` |
| S3 | `y × A1` | `t ← t − P + s2` |
| S4 | `xr × B2` | `u ← P` |
| S5 | `y × A2` | `s2 ← u − P`; `s1 ← t`; `done ← 1` |

(`P` — выход умножителя.) Порядок важен: `s1` использует **старое** `s2` (S3), `s2` обновляется последним (S5). Между двумя `start` должно пройти не менее 6 тактов. При тактовой частоте хотя бы в сотни кГц против Fs = 10 кГц запаса хватает с огромным избытком — именно поэтому один умножитель здесь применим.

Обе структуры должны давать **побитово одинаковые** выходы, совпадающие с `df2t_fixed.m`.

Дальше — код: сначала структура A, затем B. Пока этапы 1–5 не пройдены, к нему приступать не стоит.

## §11. Тесты и приёмка

**Ручной ввод в VWF.** Для каждого отсчёта нужен свой отрезок значения шины `x`, поэтому в VWF идут только короткие тесты (≤ 24 отсчётов). Длинные (синус 100 Гц / 2 кГц, меандр) оцениваются в MATLAB.

Настройка VWF для фильтра:

1. `clk`: период 100 нс. `reset_n`: 0 в начале, потом 1.
2. `start`: **Overwrite Clock**, период **800 нс**, Duty **12,5 %** (**?**). Проверьте на экране: единица должна накрывать ровно один нарастающий фронт `clk` и начинаться/заканчиваться на спаде `clk`; при необходимости подберите Offset.
3. `x[15..0]`: Radix **Signed Decimal**; смена значений — в моменты начала импульсов `start` (то есть на спаде `clk`, не на фронте).
4. `y[15..0]`: Radix **Signed Decimal**. Значение отсчёта `n` читайте после `done` — через столбец *Value at* и мастер-маркер времени.

| Тест | x[n] | Где | Ожидаемый y[n] |
|---|---|---|---|
| T0 нули | 0 × 16 | VWF | 0 везде |
| T1 импульс | x[0] = 10000, далее 0 | VWF | 201, 715, 1188, 1396, 1417, 1317, 1147, 946, 741, 550, 383, 245, 137, 57, 1, −35 |
| T2 ступенька | 10000 × 24 | VWF | 201, 916, 2104, 3500, 4917, 6234, 7381, 8327, 9068, 9618, 10001, 10246, 10383, 10440, 10441, 10406, 10351, 10287, 10223, 10164, 10113, 10071, 10038, 10013 |
| T3 смена знака | 10000 × 12, затем −10000 × 12 | VWF | 201, 916, 2104, 3500, 4917, 6234, 7381, 8327, 9068, 9618, 10001, 10246, 9981, 8607, 6231, 3403, 513, −2185, −4543, −6494, −8027, −9168, −9966, −10480 |
| T4 насыщение | 32767 × 24 | VWF | 658, 3001, 6894, 11469, 16114, 20430, 24188, 27287, 29714, 31515, **32767, 32767**, 32766, 32764, … (`sat = 1` на n = 10, 11) |
| T5 синус | 100 Гц и 2 кГц, 200 отсчётов | MATLAB | e_FS ≈ 0,02 % / 0,01 % |
| T6 меандр | 250 Гц, 200 отсчётов | MATLAB | e_FS ≈ 0,01 % |

Критерии приёмки:

1. T0–T4 в VWF **побитово** совпали с `df2t_fixed.m` (и с таблицей выше).
2. По всем тестам в допустимом диапазоне входа `e_FS ≤ 2 %` (фактически ≈ 0,02 %).
3. Насыщение (`sat = 1`) происходит только в T4.
4. Обе структуры дают одинаковый `y[n]`.

**Запасной путь для длинных сигналов.** Если понадобится прогнать сотни отсчётов через сам AHDL-проект: NativeLink RTL-симуляция для AHDL не работает (нет HDL-файлов). Возможна только gate-level функциональная симуляция по netlist (**Tools → Run Simulation Tool → Gate Level Simulation**) с Verilog-тестбенчем, читающим x[n] из файла. Это отдельная задача — если понадобится, разберём отдельно.

## §13. Типичные проблемы

| Симптом | Причина | Что делать |
|---|---|---|
| При запуске симуляции — ошибка `vsim`/«-novopt» | устаревший ключ в `.do` | *Simulation Settings*: `-novopt` → `-voptargs="+acc"`, при неудаче удалить ключ |
| ModelSim/Questa не запускается | неверный путь в *EDA Tool Options* | указать папку с `vsim.exe` |
| Ошибка лицензии `vsim` (unable to checkout) | Questa без лицензии | этап 0.2, вариант A: `LM_LICENSE_FILE`, перезагрузка, `lmutil lmdiag` |
| Node Finder пуст | не выполнена компиляция после последних правок | Start Compilation, затем *List* |
| В результате везде `X`/`U` | не задан сброс; вход менялся на фронте; узлы добавлены до перекомпиляции | сброс в начале, смена входов на спаде clk, удалить и добавить узлы заново |
| Отрицательные числа выглядят положительными | шина в *Unsigned* | Radix → *Signed Decimal* |
| Ошибка «signed/size mismatch» при сложении | операнды разной ширины | расширить знак вручную (§10.1) |
| Фильтр «уходит в максимум» | перепутан знак A1/A2; неверный сдвиг; состояния урезаны | сверить с `df2t_fixed.m`, ширина состояний 36 бит |
| Отличие от MATLAB на один отсчёт | момент чтения `y` или порядок обновления `s1`/`s2` | читать после `done`, сначала `s1` (по старому `s2`), потом `s2` |
| Отличие от MATLAB на ±1 LSB | округление: аппаратно «+2^14 и отсечь», в MATLAB стоял `round()` | использовать `df2t_fixed.m` |
